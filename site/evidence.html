How to read this

Evidence stage matters more than a green number.

A configuration can make money in a historical export while individual components inside it remain unproven. Signal Bridge will keep those layers separate.

Implemented

The code can do it.

This only establishes that a rule or filter exists in code. It does not establish edge.

Backtested

A full configuration was tested.

Useful historical evidence, but still vulnerable to configuration bias, regime dependence, costs, and interactions among components.

Isolated attribution

The component itself was tested.

This is the stronger answer to “does this filter help?” because the comparison controls the rest of the system.

Walk-forward

Out-of-sample durability.

Reserved for evidence that survives a properly separated validation window rather than the same development sample.

Paper forward

Observed in live market sequence.

Forward evidence is tracked separately from backtests so hindsight does not quietly leak into results.

Live

Real execution evidence.

Eventually reserved for actual live execution records — never inferred from paper trading or alerts firing.

Current conclusions

What the table does and does not tell us.

  • Win rate alone is not enough: R1.2 has the highest win rate in this table but negative net profit and PF below 1.
  • V6 is the strongest historical configuration in this specific export set: it has the largest net profit and highest PF here, but its duplicate row is not independent confirmation.
  • R1.3 is a different instrument/timeframe/sample: its lower drawdown cannot be attributed to “confluence” alone without controlled attribution.
  • Midpoint, VWAP, EMA, displacement, range filters, and retest logic must be tested component-by-component: profitable system-level results do not prove each one.
  • Negative results are product content too: R1.2 stays in the record because learning what failed is part of the research journey.
