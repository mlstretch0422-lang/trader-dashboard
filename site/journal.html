Capture Architecture

Write once. Reuse everywhere.

The live workflow is fast enough for an actual trading morning: journal in Discord, preserve the original note, structure it later, connect it to Signal Bridge events, and decide whether it stays private or becomes a public case study.

01Discord journal postFast note while the trade and decision are still fresh.
02Private captureSigned Discord interaction stores the raw note, screenshot reference, and provenance in D1.
03StructureSymbol, direction, setup, result, tags, screenshot, and signal link become fields.
04Review / PublishKeep it private, or deliberately publish a selected entry to the website.
05ResearchPatterns across entries become strategy questions, education, and future tests.
Private-first by design. Capture to Journal and normal /journal entries remain private. Server managers can deliberately use Publish to Journal or publish:true to move a selected note/screenshot onto this public page.

The configured trade-journal channel now has a private workflow and an explicit publish workflow. Nothing has to become public just because it was captured.

/journal

Structured capture for note, symbol, side, result, setup, strategy/version, P&L, R multiple, and chart. Leave Publish off for private capture; server managers can set it true for a selected website entry.

Capture to Journal

Use the message context command on a normal Discord post to preserve the original text, provenance, and first attachment privately without retyping it.

Publish to Journal

Server managers can right-click a selected journal message and publish it. If that message was already captured privately, Signal Bridge promotes the existing record instead of duplicating it.

Screenshot storage note: published Discord attachment URLs can render now, but Discord CDN links are not the long-term archive. Durable member media storage is part of the account/auth layer so screenshots remain available independently of Discord.
